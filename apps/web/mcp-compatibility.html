MCP compatibility

Last tested November 8, 2026, against Portifact 0.11.0. Codex CLI token refresh and the comment tools were checked again the same day against Portifact 0.13.0.

Portifact runs a remote MCP server at https://app.portifact.com/mcp (Streamable HTTP). Add it to your client and sign in with your Portifact account in the browser. The first sign-in asks only to see your artifacts; your client asks again when a tool needs more, such as publishing or deleting.

Claude.ai

Add a custom connector with the server address and sign in. The first time Claude publishes, it asks you to allow publishing as well. The connector shows 24 tools: 9 that only read and 15 that write or delete.

Claude Code

Add the server with claude mcp add --transport http portifact https://app.portifact.com/mcp, then choose it in /mcp and sign in. When a tool needs access you have not given yet, the call fails with a message that names the missing permission. Run /mcp, choose Re-authenticate and allow it; Claude Code keeps what you allowed before. Non-interactive runs (claude -p) cannot sign in, so do it in an interactive session first.

Codex CLI

Add the server with codex mcp add portifact --url https://app.portifact.com/mcp; Codex starts the sign-in right away. Codex does not ask for more access on its own, so sign in with everything your agent will need, for example:

codex mcp login portifact --scopes artifacts:read,artifacts:write,artifacts:delete,offline_access

Add annotations:read, annotations:write or annotations:moderate for the comment tools; with all three, Codex turned comments on, commented, replied, resolved and exported the comments of a document. Codex asks you to approve tools that delete before it runs them. It renews its access on its own when the hour-long token expires.

Other clients

Any client that supports remote MCP servers with OAuth should work: Portifact follows the MCP authorization specification of 2026-07-28 and also accepts dynamic client registration and the 2025 protocol revisions. If yours does not, the portifact CLI and the agent skill work in every agent with a shell. Tell us about it on GitHub.
