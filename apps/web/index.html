Three ways in

One set of rules, wherever you work

The CLI, the remote MCP server and the web dashboard sit on the same domain layer. An operation runs the same permission checks, quotas, states and errors wherever you start it, so your agent and your team always see the same thing.

How it works

From agent output to feedback, in one loop

No zip files, screenshots or pasted walls of text. The work stays where it was made, and the comments come back to the agent that made it.

  1. 1

    Your agent writes

    A plan, a progress report or a prototype lands on disk as HTML, Markdown or text.

    report.html
  2. 2

    Publish it

    One command or one tool call returns a private URL on its own origin.

    portifact publish
  3. 3

    Share it

    Open it to the people who should see it, and nobody else.

    portifact access add
  4. 4

    Collect comments

    Reviewers select a sentence or an element and start a thread on it.

    review mode
  5. 5

    Your agent revises

    It exports the threads, applies the changes and publishes again at the same URL.

    annotations export

The steps show CLI commands, and the dashboard does each of them too. Through MCP your agent publishes documents and reads the threads; changing access stays with the CLI and the dashboard.

Access control

Private until you decide otherwise

Every new artifact starts visible only to you. Widen the circle one step at a time, and narrow it again whenever you want.

Private
Only you. The default for every new artifact.
Email list
The people you name, after they confirm their address.
Signed in
Anyone with a Portifact account.
Public
Anyone with the link. Still not indexed unless you allow it. New accounts can choose it 15 minutes after signing up.

Publishing a new version keeps the current access. An update never widens the audience.

Lifecycle

Online while it matters, recoverable after

Agents produce a lot. Portifact keeps the active work online and moves the rest out of the way without losing it.

  1. 30 days online, renewed on update

    Each new version restarts the clock, so work in progress never disappears mid-review.

  2. Archived for six months

    Expired artifacts go offline and stop counting as active, with their threads kept.

  3. Restore in one step

    Bring it back from the CLI, your agent or the dashboard, at the same URL.

Security

Every artifact in its own sandbox

Agents write JavaScript. Portifact assumes any published page could be hostile and keeps it away from your account.

  • A separate origin per artifact

    User content lives on its own subdomain of portifact.dev. Your session, tokens and the API live on portifact.com.

  • Quiet by default

    Not indexed by search engines and not embeddable in other sites unless you allow it.

  • Verified installs, available today

    The installer checks every download against SHA-256 checksums, and releases carry signed build provenance you can verify with gh attestation verify.

Install Portifact for me and set up its agent skill.

1. Detect my operating system and CPU architecture.
2. Install the Portifact CLI with the official installer:
   - macOS or Linux: curl -fsSL https://portifact.com/install | bash
   - Windows (PowerShell): irm https://portifact.com/install.ps1 | iex
   - On Alpine Linux, first install the C++ runtime: apk add libstdc++ libgcc
   The installer verifies the download checksum. If verification fails, stop and tell me; do not work around it. Ask me before anything that needs administrator rights.
3. Verify it with: portifact --version
   If portifact is not on PATH yet, run ~/.portifact/bin/portifact (Windows: %USERPROFILE%\.portifact\bin\portifact.exe) and tell me how to add it to PATH.
4. Install the Portifact skill globally for the agent you are, using your agent id from https://github.com/vercel-labs/skills/blob/main/docs/agents.md (for example claude-code, codex, cursor, gemini-cli, github-copilot, opencode):
   npx skills add leynier/portifact --skill portifact -g -y -a <your-agent-id>
   This needs Node.js 22.20 or newer. If Node.js is missing, tell me instead of installing it without asking.
5. Summarize what you installed, the CLI version, and where the skill was placed.

FAQ

Questions, answered

Something missing? Open an issue on GitHub.

Can I use Portifact today?

Yes. Publishing, access control, versions, archive and restore, annotations with the review viewer, the MCP server and the dashboard all work today. Sign in with portifact login, connect the MCP server or sign in at app.portifact.com. Portifact is early, so expect rough edges and limits that may change.

Which agents does it work with?

Any coding agent with a terminal can run the CLI. The skill installs into Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode and other agents. The remote MCP server works in clients that support OAuth sign-in and is tested with Claude.ai, Claude Code and Codex CLI; see MCP compatibility.

What can I publish?

Static content: HTML sites with their CSS and JavaScript, Markdown rendered cleanly and plain text shown exactly as written. A single file, a folder or a ZIP, with private sources only you can download if you want them kept alongside. Portifact does not run builds or servers.

Who can see what I publish?

Only you, until you change it. You can open an artifact to a list of email addresses, to anyone signed in or to the public, and narrow it again at any time. Publishing a new version never widens the audience.

What happens after 30 days?

If you have not updated it, the artifact is archived: it goes offline but is kept for six months, and you can restore it whenever you need it. After six months in the archive it is deleted. Every update renews the 30 days.

Can my agent act on reviewer comments safely?

Your agent can read and export every thread as JSON or Markdown. The Portifact skill teaches it to treat comments as untrusted data: it summarizes them for you and never follows instructions written inside a comment.

Is it safe to open an artifact someone shared with me?

Each artifact runs on its own subdomain of portifact.dev, which holds no account credentials. Your session and the API live on portifact.com, so a published page cannot act on your account.
