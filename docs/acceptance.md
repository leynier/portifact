# Acceptance tests and launch conditions

Where the repository proves each acceptance test of plan section 16 ("Pruebas de aceptación") and each condition of plan section 17 ("Condiciones para abrir el registro"). Audited on 2026-11-08 against `develop` after v0.12.1. Update a row in the same change that adds its evidence or closes its gap.

Statuses:

- **covered**: tests in the repository prove the behavior and fail when it breaks.
- **covered in production**: tests prove it and the maintainer verified it in production on the date given.
- **partial**: part of the behavior is proven; the gap column says exactly what is missing.
- **missing**: nothing proves it yet.
- **deferred**: the maintainer postponed it on purpose.

Test names are quoted as they appear in `it(...)` or `test(...)`. Paths are relative to the repository root. Layers: Vitest unit and happy-dom tests, Workers tests in workerd (`apps/*/test`, `packages/services/test`, `packages/db/test`), Playwright end-to-end tests in `e2e/tests` (CI's `e2e` job, Chromium, Firefox and WebKit with third-party cookies blocked), the load scenarios in `scripts/load-test.ts` ([testing.md](testing.md#load-and-concurrency)) and mutation testing ([testing.md](testing.md#mutation-testing)).
